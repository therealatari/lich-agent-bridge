# Registered capabilities

Capabilities are named operations, not an arbitrary command executor.
Discover the live catalog and argument schemas through SessionHub, MCP, or CLI;
configured availability and admission checks determine what can run.

## Public baseline

The bridge supports structured state reads, recorded knowledge queries,
registered character inspection, exact-item auditing, and bounded operation
infrastructure. INFO/SKILLS recon is the only game-command evidence tool exposed
to the answer model.

No character-specific hunt preparation profile or combat controller is bundled.
The empty shared controller manifest is deliberate. Generic infrastructure
must not silently invent a strategy for an unconfigured character.

## Adding an operation

1. Define the intended observation or action and obtain the required authority.
2. Specify starting identity, freshness, ownership, and resource requirements.
3. Validate a narrow argument schema before submitting any command.
4. Bind exact IDs and enforce broker plus local bridge checks.
5. Define attributable success evidence, terminal failures, and safe handoff.
6. Test stale state, replacement, cancellation, expiry, rejection, and conflicts.
7. Request a separate authorized live smoke test after isolated verification.

Prefer an existing maintained script interface or configuration option when it
already provides the required behavior. A new operation is not permission to
add unrelated command authority.

See [Developer testing](Developer-Testing.md) and [Safety](Safety.md).
